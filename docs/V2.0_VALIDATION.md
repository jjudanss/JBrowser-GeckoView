# JBrowser 2.0.0 validation notes

## Static checks in the authoring environment

- Android manifest XML parsed successfully.
- Gradle files and GitHub Actions workflow reviewed.
- Built-in filter engine source and filter-list asset removed from the active app.
- `MainActivity` now references GeckoView rather than Android WebView.
- GeckoView API usage cross-checked against Mozilla's current consumer documentation and Java API references.

## Not verified here

- A full Gradle/Android SDK build could not be run in this environment because Android SDK and Gradle are not installed.
- The GeckoView AAR must be downloaded by the GitHub Actions runner; the dependency is large, so the first build may take longer than the old WebView build.
- No real Android TV hardware is available here for pointer, extension, video/DRM, remote-control or memory testing.
- The AMO web installer path depends on GeckoView Add-on Manager web API compatibility with the specific Add-ons website flow. The local XPI install path is also provided.

## Technical constraints

- Minimum Android API was raised to 26 (Android 8.0), matching current GeckoView support.
- GeckoView remote XPI installs require Mozilla-signed packages.
- GeckoView-compatible Firefox WebExtensions are supported; Chrome Web Store extensions are not.
- Video codecs, DRM, HDR and maximum resolution depend on the TV hardware and streaming provider.

# JBrowser 2.1.0 ABI and APK optimization plan

## What changed

The Android Gradle build uses ABI splits for four GeckoView-supported CPU families:

- `arm64-v8a`
- `armeabi-v7a`
- `x86`
- `x86_64`

`universalApk` is disabled. The workflow inspects each generated APK and fails unless it contains exactly one ABI. It then creates individually named APK artifacts and release assets.

Release builds enable R8 code shrinking and Android resource shrinking. This primarily optimizes JBrowser's own Java and Android resources. GeckoView's native browser engine is precompiled native code, so R8 does not substantially shrink it.

Native libraries are compressed in APKs to prioritize download size. Android extracts these libraries during installation; therefore, installed storage usage can be larger than the APK download size. This is a download-size optimization, not a guarantee of lower installed footprint or lower RAM usage.

## Why multiple APKs

A universal APK includes native libraries for multiple CPU architectures. A split APK includes only the native libraries for its ABI. Android's official Gradle ABI split mechanism supports this packaging model. See the Android Developers guide: https://developer.android.com/build/configure-apk-splits

Mozilla lists GeckoView support for ARMv7, ARM64, x86 and x86_64: https://wiki.mozilla.org/Mobile/GeckoView

## Size expectations

The previous universal build was reported by the user as approximately 500 MB. A per-ABI APK should be materially smaller because it no longer packages every ABI. Historical ARM64 GeckoView 157 AAR metadata lists an AAR size around 86.2 MB; newer versions and final APK sizes differ. This figure is not a measured size for GeckoView 160 or JBrowser 2.1.0.

No fixed size or under-100-MB result is guaranteed. GitHub Actions will print the actual size of each APK after building.

## Testing required

- Verify each APK has exactly one ABI.
- Install each ABI variant on a matching device/emulator.
- Test startup, page rendering, pointer input, extension install/enable/disable, tabs and video.
- Confirm R8 has not broken extension callbacks or GeckoView integration.
- Compare compressed download size and installed storage usage.

## Signing

The workflow uses the runner's debug signing key for side-loading. A persistent keystore stored as GitHub Actions secrets is needed for stable in-place upgrades across builds.
